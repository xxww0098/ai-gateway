# 项目树优化：决策记录

本记录只审计本轮代用户作出的选择，不替代代码审查。设计选择裁决为 sound（合理）；中等置信度项应优先由用户阅读。实现者一度用自身拆分范围验证自身输出，漏掉 4 个 helper；该验证方法不成立，已由根代理恢复原文并改用完整清单守恒检查、编译和真实测试，不采用实现者的初次自证作为验收。

## Sound · 中等置信度：先优化后端，前端只交付设计

- **何时**：本轮范围确定时。
- **选择与场景**：用户要求审查和优化树，却没有指定模块。仓库已有大量在途变更，工程契约还限定前端只读。假设此时把所有目录整体搬迁，现有改动的归属和回归范围都难以区分；本轮改为修后端已失败的结构门禁，前端给出分层次序，不修改页面。
- **未指定处**：要优化多深、是否同时改 UI。
- **影响**：前端倒置依赖仍需后续工作；这次不构成全仓完成重构。
- **裁决**：sound。低风险范围可单独验收，且不把资金和界面改造混入。

## Sound · 中等置信度：复用 model 的订阅日历

- **何时**：检查 hold 的重复职责时。
- **选择与场景**：管理员创建订阅时，model 计算下个 UTC 月初；代理准入时原来又自己算一遍。两份公式可能各自被修改，导致创建和扣费周期不一致。本轮让代理直接使用 model 的函数，原来调用 hold 函数的代码不必换接口。
- **未指定处**：用户没有指定公式归属，也未指定极端日期的失败方式。
- **影响**：未来日历变更只有一个实现位置。正常日期的重置点不变；Chrono 日期上限无法表示下一周期时改为沿用 model 的 fallback，而不是代理的溢出 panic。
- **裁决**：sound。共享同一规则比保留两个“目前一样”的算法更可靠；不改变配额软硬性质或事务。

## Sound · 高置信度：保留 crate 和公开入口，在内部拆职责

- **何时**：为两个 OAuth 模块分派独占写入范围时。
- **选择与场景**：Kiro 收到一个二进制事件帧，原请求文件既要拼请求又要读帧头和 CRC。拆出私有 codec 后，消费者仍调用原 request API，编译依赖和协议行为无需同时迁移。Antigravity 同理：缓存和响应转换分开，但不会各自新建一份共享状态。
- **未指定处**：拆文件还是拆 crate，是否重命名对外接口。
- **影响**：后续维护者可以按变化原因定位模块，不产生新依赖、服务或兼容 wrapper。
- **裁决**：sound。子代理的选择符合这一明确合同；Kiro 的被移动函数体经根代理逐字比较保持一致。

## Sound · 高置信度：资金一致性单独验收

- **何时**：核实 README 的支付幂等承诺时。
- **选择与场景**：订单先记 paid，进程随即退出，余额尚未更新。挪动文件不能防止这种损失；仓库已有专门加固方案。此次更正文档承诺并保留证据，而不是顺手改变 SQL 事务、入账去重或 Redis 恢复源。
- **未指定处**：发现业务风险后是否扩大为资金修复项目。
- **影响**：P1 风险仍未关闭；需要真实数据库失败用例和独立事务设计。
- **裁决**：sound。明确未完成的保证比在目录重构中悄悄改变钱的语义更安全。

## Sound · 高置信度：修复验证暴露的测试端问题

- **何时**：全量与相关套件执行失败后。
- **选择与场景**：测试 HTTP server 在 macOS 上继承非阻塞 socket，在请求尚未到达时断连；另一个断言期待旧名称 xai，而现有协议注册约定已是 grok。它们使回归验收失真。
- **未指定处**：是否扩大写入范围到两个测试文件。
- **影响**：只修 fixture 的 socket 模式及陈旧名称断言，不改生产客户端、provider 名称或业务断言强度。
- **裁决**：sound。本机最小实验与现有失败用例给出了依据；不能用重跑直到绿、删断言或增加 ignore 替代修复。
